interface HRCompensationGameState {

## 🎯 Game Mechanics

### Stage 1: Expert Selection
**Objective:** Choose experts with high credibility

**Scoring:**
```
Expert Selection Score = (Average Credibility) × ₹50,000
Range: ₹0 - ₹50,000 (5.3% of max bonus)
```

**Experts:**
| Name | Specialty | Credibility | Cost |
|------|-----------|-------------|------|
| Dr. Sarah Johnson | Compensation Strategy | 0.9 (hidden) | ₹5,000 |
| Prof. Raj Patel | Talent Acquisition | 0.85 (hidden) | ₹4,000 |
| Ms. Emily Chen | Market Analysis | 0.7 (hidden) | ₹3,000 |
| Mr. David Brown | Performance Metrics | 0.6 (hidden) | ₹2,000 |

---

### Stage 2: Attribute Weighting
**Objective:** Assign weights close to optimal weights

**Scoring:**
```
Weight Difference = Σ |player_weight - optimal_weight|
Attribute Weight Score = (1 - Weight Difference) × ₹1,00,000
Range: ₹0 - ₹1,00,000 (10.5% of max bonus)
```

**Attributes:**
| Attribute | Optimal Weight (hidden) |
|-----------|-------------------------|
| Technical Skills | 0.35 (35%) |
| Leadership Ability | 0.25 (25%) |
| Experience | 0.20 (20%) |
| Education | 0.10 (10%) |
| Cultural Fit | 0.10 (10%) |

---

### Stage 3: Candidate Ranking
**Objective:** Rank candidates to match optimal ranking

**Scoring:**
```
Spearman Correlation = 1 - (6 × Σd²) / (n × (n² - 1))
Ranking Match Score = ((Correlation + 1) / 2) × ₹3,00,000
Range: ₹0 - ₹3,00,000 (31.6% of max bonus)
```

**Optimal Ranking (hidden):**

2. Bob Martinez (Rank 2)
3. Carol Lee (Rank 3)
4. Dan Wilson (Rank 4)

---

### Final Compensation
```
Final Compensation = Base Salary + Total Score

Base: ₹5,00,000
Max Total: ₹4,50,000
Max Final: ₹9,50,000
```

## 🚀 How to Use

### 1. Start Backend
```bash
cd backend
npm run dev
```

### 2. Create Session (Facilitator)
```bash
curl -X POST http://localhost:4000/api/sessions \
  -H "Authorization: Bearer {facilitator_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "simulationSlug": "hr-compensation",
    "sessionName": "HR Workshop - Batch A",
    "configuration": {},
    "maxRounds": 1
  }'
```

### 3. Join Session (Participant)
```bash
curl -X POST http://localhost:4000/api/sessions/{sessionId}/join \
  -H "Authorization: Bearer {participant_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "playerName": "Student Name",
    "role": "PLAYER"
  }'
```

### 4. Start Session (Facilitator)
```bash
curl -X POST http://localhost:4000/api/sessions/{sessionId}/start \
  -H "Authorization: Bearer {facilitator_token}"
```

### 5. Play via Socket.IO
See `HR_COMPENSATION_API_GUIDE.md` for complete Socket.IO integration examples.

## 📊 Data Flow

```
┌─────────────────────────────────────────────────────────────┐
│                    HR COMPENSATION FLOW                      │
└─────────────────────────────────────────────────────────────┘

1. SESSION CREATION
   ├─ POST /api/sessions
   ├─ simulationSlug: "hr-compensation"
   └─ Creates session in SETUP status

2. PARTICIPANT JOIN
   ├─ POST /api/sessions/:id/join
   └─ Single player joins (max_players: 1)

3. SESSION START
   ├─ POST /api/sessions/:id/start
   ├─ Initializes HRCompensationEngine
   └─ Status: IN_PROGRESS

4. SOCKET CONNECTION
   ├─ socket.emit('join_session', { sessionId, participantId })
   └─ Receives initial state (stage: 'expert-selection')

5. STAGE 1: EXPERT SELECTION
   ├─ socket.emit('player_action', { stage: 'expert-selection', data: { expertIds } })
   ├─ Engine calculates expertSelectionScore
   └─ Advances to 'attribute-weighting'

6. STAGE 2: ATTRIBUTE WEIGHTING
   ├─ socket.emit('player_action', { stage: 'attribute-weighting', data: { weights } })
   ├─ Engine calculates attributeWeightScore
   └─ Advances to 'candidate-ranking'

7. STAGE 3: CANDIDATE RANKING
   ├─ socket.emit('player_action', { stage: 'candidate-ranking', data: { ranking } })
   ├─ Engine calculates rankingMatchScore + finalCompensation
   ├─ Reveals optimal values
   └─ Stage: 'complete', isComplete: true

8. METRICS & REPORT
   ├─ Frontend displays final compensation
   ├─ Shows score breakdown
   ├─ Compares with optimal decisions
   └─ GET /api/sessions/:id/report (facilitator)
```

## 🚨 Known Limitations

1. **Single Player Only:** Currently supports 1 participant per session
2. **No Round Advancement:** Stage-based, not round-based (maxRounds should be 1)
3. **No Bots:** Does not support bot participants
4. **No Pause/Resume:** Once started, must complete all stages
5. **No Stage Reversion:** Can't go back to previous stages
